====================================================================
YAML解説
====================================================================

このファイルは、employee-portalプロジェクトで使っている3つの
CloudFormationテンプレート（infra/hosted-zone.yaml、infra/certificate.yaml、
template.yaml）に、行ごとの日本語コメントを付けた「読む用」のコピーです。

実際にデプロイで使うYAMLファイル本体（GitHub上のもの）はコメントを含まない
ASCII専用の状態に戻してあります。理由は以下の通りです。

  デプロイ元のWindows端末のAWS CLIには、テンプレートファイルの読み込み時に
  システムの既定コードページ（cp932）でデコードしようとして、日本語などの
  非ASCII文字を含むファイルを正しく読めないという不具合があります。
  そのため実際にデプロイに使うYAMLは日本語を含めない（DynamoDBの属性名など
  どうしても必要な日本語だけは \uXXXX のようなエスケープ表記で埋め込む）
  運用にしており、日本語コメントで内容を説明したい場合は、このファイルの
  ように別のテキストファイルに分けています。

以下、3ファイル分の内容と解説です。


====================================================================
【1】infra/hosted-zone.yaml
====================================================================
役割: portal.tokaiec.co.jp 専用のRoute53パブリックホストゾーンを作成する。
      tokaiec.co.jp 本体のゾーンはさくらインターネット側のまま変更しない。
      3段階デプロイの最初（ステージ1）に実行する。

--------------------------------------------------------------------

# CloudFormationテンプレートのフォーマットバージョン（固定値、AWSが決めている唯一の値）
AWSTemplateFormatVersion: '2010-09-09'
# このテンプレート全体の説明文（CloudFormationコンソールのスタック詳細に表示される）
Description: >
  Route53 public hosted zone for portal.tokaiec.co.jp.
  The tokaiec.co.jp zone itself stays on Sakura Internet's DNS;
  only this subdomain is delegated to Route53.
  (実際のYAML本体ではASCII専用にする理由もここに書いてある)

# デプロイ時に外部から値を渡せる入力パラメータの定義
Parameters:
  # 対象ドメイン名。--parameter-overridesで上書きしない限りDefaultの値が使われる
  DomainName:
    Type: String
    Default: portal.tokaiec.co.jp

# このテンプレートが実際に作成するAWSリソースの定義
Resources:
  # Route53のパブリックホストゾーンを1つ作成する（このテンプレートが作るリソースはこれだけ）
  HostedZone:
    Type: AWS::Route53::HostedZone
    Properties:
      # ゾーン名。DomainNameパラメータの値（portal.tokaiec.co.jp）がそのまま使われる
      Name: !Ref DomainName

# スタック作成後に`describe-stacks`で取得できる出力値
Outputs:
  # ホストゾーンの物理ID。証明書スタック(certificate.yaml)や本体スタック(template.yaml)へ
  # パラメータとして渡すために必要
  HostedZoneId:
    Value: !Ref HostedZone
  # AWSが自動割り当てした4件のネームサーバー名。
  # さくらインターネット側にNSレコードとして登録することで、DNS委任が成立する
  NameServers:
    Description: Delegate "portal" as NS records at Sakura to these 4 name servers
    Value: !Join [", ", !GetAtt HostedZone.NameServers]

【2】infra/certificate.yaml
====================================================================
役割: portal.tokaiec.co.jp 用のACM証明書（HTTPS化に使う）を発行する。
      CloudFrontで使う証明書は必ずus-east-1（バージニア北部）リージョンで
      発行する必要があるため、他の2ファイルとリージョンが異なる。
      ステージ1のホストゾーンにNS委任が反映された後（ステージ2完了後）、
      ステージ3として実行する。

--------------------------------------------------------------------

# CloudFormationテンプレートのフォーマットバージョン（固定値）
AWSTemplateFormatVersion: '2010-09-09'
Description: >
  ACM certificate for portal.tokaiec.co.jp (must be deployed in us-east-1
  for use with CloudFront). Deploy after hosted-zone.yaml, and only once
  the NS delegation at Sakura has propagated.

Parameters:
  # 証明書の対象ドメイン名
  DomainName:
    Type: String
    Default: portal.tokaiec.co.jp
  # hosted-zone.yamlのOutputsから受け取る、検証レコードを書き込む先のゾーンID
  HostedZoneId:
    Type: String
    Description: hosted-zone.yaml Outputs.HostedZoneId

Resources:
  # ACM証明書を1つ発行する（このテンプレートが作るリソースはこれだけ）
  Certificate:
    Type: AWS::CertificateManager::Certificate
    Properties:
      # 証明書の対象ドメイン
      DomainName: !Ref DomainName
      # DNSによる所有権検証を使う（メール検証ではない）
      ValidationMethod: DNS
      # DNS検証の詳細設定。HostedZoneIdを指定しているため、
      # CloudFormationが検証用CNAMEレコードを自動的にRoute53へ書き込んでくれる
      # （手動でCNAMEをコピーして登録する手間が不要になる）
      DomainValidationOptions:
        - DomainName: !Ref DomainName
          HostedZoneId: !Ref HostedZoneId

Outputs:
  # 発行された証明書のARN。本体スタック(template.yaml)のAcmCertificateArnパラメータに渡す
  CertificateArn:
    Value: !Ref Certificate

【3】template.yaml（本体スタック）
====================================================================
役割: アプリ本体一式（DynamoDB・S3×2・Cognito×2・API Gateway・Lambda×4・
      CloudFront・Route53のAレコード）をまとめて作成する。ステージ1・3の
      成果物（ホストゾーンID・証明書ARN）を受け取って構築する、最後の
      ステージ4で実行する。

--------------------------------------------------------------------

# CloudFormationテンプレートのフォーマットバージョン（固定値）
AWSTemplateFormatVersion: '2010-09-09'
# SAM（Serverless Application Model）の簡略記法を使うための宣言。
# これを書くと、AWS::Serverless::Function のような短い書き方が、デプロイ時にCloudFormationの
# 正式なリソース定義（Lambda本体+IAMロール+イベント設定など）へ自動展開される。
# この展開処理自体もAWS管理のLambda（マクロ）で行われるため、デプロイ時に
# --capabilities CAPABILITY_AUTO_EXPAND の指定が必要になる。
Transform: AWS::Serverless-2016-10-31
# テンプレート全体の説明（CloudFormationコンソールのスタック詳細に表示される）
Description: >
  Employee information portal (S3 static hosting + API Gateway + Lambda + DynamoDB + Cognito).
  CSV import (keyed by employee number) / self-service view & edit / CSV export (manual, by an admin).

# Lambda関数（AWS::Serverless::Function）全体に共通して適用されるデフォルト設定。
# 各関数で個別に上書きしない限りこの値が使われる。
Globals:
  Function:
    Runtime: python3.12   # 全Lambda共通のランタイム
    Timeout: 30            # 秒。個別の関数でTimeoutを指定すればこちらが優先される
    MemorySize: 128        # MB

# デプロイ時に外部（コマンドラインの--parameter-overrides）から値を渡せる入力パラメータ
Parameters:
  # 独自ドメイン名。CloudFrontのAliasesやRoute53のレコード名に使う
  DomainName:
    Type: String
    Default: portal.tokaiec.co.jp
  # infra/certificate.yaml（us-east-1）が発行したACM証明書のARN。CloudFrontにアタッチする
  AcmCertificateArn:
    Type: String
    Description: Outputs.CertificateArn from infra/certificate.yaml (us-east-1)
  # infra/hosted-zone.yamlが作成したRoute53ホストゾーンのID。CloudFront向けAレコードを置く先
  HostedZoneId:
    Type: String
    Description: Outputs.HostedZoneId from infra/hosted-zone.yaml
  # CloudFront->S3間だけで使う秘密のReferer値。S3直アクセスを遮断するために使う。
  # NoEcho: trueなので、コンソールやCLI出力にこの値そのものは表示されない
  OriginVerifySecret:
    Type: String
    NoEcho: true
    MinLength: 16
    Description: >
      Secret value CloudFront forwards to the S3 origin as a Referer header,
      used to block direct access to S3 (e.g. generate with `openssl rand -hex 16`).

# ここから実際に作成されるAWSリソースの定義
Resources:

  # --------------------------------------------------------------------
  # DynamoDB: 従業員マスタ（PK = 社員番号属性）
  # --------------------------------------------------------------------
  # 従業員マスタを1件=1従業員で保持するテーブル。属性はスキーマレス（CSVの列がそのまま属性になる）で、
  # ここで明示的に定義するのはパーティションキー（社員番号）だけでよい。
  EmployeeTable:
    Type: AWS::DynamoDB::Table
    Properties:
      # オンデマンド課金。使った分だけ課金され、事前のキャパシティ設計が不要
      BillingMode: PAY_PER_REQUEST
      # パーティションキーとして使う属性の型を宣言（DynamoDBでは主キーの属性だけ事前定義が必要）
      AttributeDefinitions:
        - AttributeName: "社員番号"
          AttributeType: S  # 文字列型
      # 実際にパーティションキーとして使う属性を指定
      KeySchema:
        - AttributeName: "社員番号"
          KeyType: HASH  # DynamoDBの用語でパーティションキーを指す（ソートキーはSORT/RANGE）

  # --------------------------------------------------------------------
  # S3: フロントエンド静的サイト用バケット
  # --------------------------------------------------------------------
  # フロントエンド（index.html/app.js/config.js）を置くバケット。静的Webホスティング機能を有効化。
  WebsiteBucket:
    Type: AWS::S3::Bucket
    Properties:
      WebsiteConfiguration:
        IndexDocument: index.html  # ルートアクセス時に返すファイル
      # S3バケットのデフォルトはパブリックアクセスを全面ブロックする設定になっているため、
      # 下のWebsiteBucketPolicyでのアクセス許可が効くように、ブロックを解除しておく
      PublicAccessBlockConfiguration:
        BlockPublicAcls: false
        BlockPublicPolicy: false
        IgnorePublicAcls: false
        RestrictPublicBuckets: false

  # WebsiteBucketへのアクセス許可を定義するバケットポリシー。
  # 「誰でもGetObject可能」に見えるが、Conditionにより実質CloudFront経由のみに絞っている。
  WebsiteBucketPolicy:
    Type: AWS::S3::BucketPolicy
    Properties:
      Bucket: !Ref WebsiteBucket
      PolicyDocument:
        Statement:
          # CloudFrontが付与する秘密のRefererヘッダーを持つリクエストのみ許可し、
          # S3静的Webホスティングエンドポイントへの直接アクセスを遮断する
          - Effect: Allow
            Principal: "*"          # 誰からのリクエストでも対象にはなるが…
            Action: s3:GetObject
            Resource: !Sub "${WebsiteBucket.Arn}/*"
            Condition:
              StringEquals:
                # …Refererヘッダーがこの秘密値と一致する場合のみ許可される。
                # この値を知っているのはCloudFront（下のOriginCustomHeadersで設定）だけなので、
                # 実質「CloudFront経由のリクエストのみ許可」という制御になる
                aws:Referer: !Ref OriginVerifySecret

  # --------------------------------------------------------------------
  # CloudFront: 独自ドメイン portal.tokaiec.co.jp 向けHTTPS配信
  # 事前に infra/hosted-zone.yaml と infra/certificate.yaml のデプロイが必要
  # --------------------------------------------------------------------
  # 独自ドメイン+HTTPSでフロントエンドを配信するCDN。S3の静的Webホスティングエンドポイントを
  # オリジン（配信元）として、HTTPSへの変換とキャッシュ、独自ドメイン対応を行う。
  CloudFrontDistribution:
    Type: AWS::CloudFront::Distribution
    Properties:
      DistributionConfig:
        Enabled: true
        DefaultRootObject: index.html  # ルートパス（/）アクセス時に返すファイル
        # このディストリビューションが応答する独自ドメイン名（CNAME相当）
        Aliases:
          - !Ref DomainName
        # HTTPS化に使う証明書の設定
        ViewerCertificate:
          AcmCertificateArn: !Ref AcmCertificateArn  # infra/certificate.yamlで発行した証明書
          SslSupportMethod: sni-only                  # SNI方式（追加コストなしで独自ドメインのHTTPS化ができる）
          MinimumProtocolVersion: TLSv1.2_2021         # 許可する最低TLSバージョン
        # 配信元（オリジン）の設定。S3の「静的Webホスティングエンドポイント」を使うため、
        # S3オリジンタイプではなく、通常のWebサーバーとして扱うCustomOriginConfigを使う
        Origins:
          - Id: WebsiteOrigin
            # WebsiteBucket.WebsiteURLは"http://bucket.s3-website-region.amazonaws.com"という形式なので、
            # スキーム(http://)を取り除いてホスト名部分だけを取り出している
            DomainName: !Select [2, !Split ["/", !GetAtt WebsiteBucket.WebsiteURL]]
            CustomOriginConfig:
              OriginProtocolPolicy: http-only  # S3静的Webホスティングエンドポイントは元々HTTPのみ対応のため
            # CloudFrontがオリジン（S3）へリクエストを転送する際に追加するヘッダー。
            # ここで秘密のRefererを付与することで、上のWebsiteBucketPolicyの条件と噛み合わせている
            OriginCustomHeaders:
              - HeaderName: Referer
                HeaderValue: !Ref OriginVerifySecret
        # デフォルトのキャッシュ・転送ルール（パスごとに個別ルールを作っていないので、これが全パスに適用される）
        DefaultCacheBehavior:
          TargetOriginId: WebsiteOrigin
          ViewerProtocolPolicy: redirect-to-https  # HTTPアクセスは自動でHTTPSへリダイレクト
          AllowedMethods: [GET, HEAD]                # 静的ファイル配信のみなのでGET/HEADで十分
          CachedMethods: [GET, HEAD]
          Compress: true                             # gzip等での自動圧縮を有効化
          ForwardedValues:
            QueryString: false   # クエリ文字列はオリジンに転送しない（キャッシュ効率のため）
            Cookies:
              Forward: none       # Cookieもオリジンへ転送しない

  # Route53にAレコード（エイリアス）を追加し、独自ドメインをCloudFrontに向ける
  DnsRecord:
    Type: AWS::Route53::RecordSet
    Properties:
      HostedZoneId: !Ref HostedZoneId  # infra/hosted-zone.yamlが作成したゾーン
      Name: !Ref DomainName
      Type: A
      AliasTarget:
        DNSName: !GetAtt CloudFrontDistribution.DomainName  # 作成したCloudFrontのドメイン名
        # CloudFrontのAliasTarget用ホストゾーンIDは固定値。全リージョン・全アカウント共通
        HostedZoneId: Z2FDTNDATAQYW2

  # --------------------------------------------------------------------
  # S3: CSV取込・出力用バケット（incoming/ にアップロードで取込トリガー）
  # --------------------------------------------------------------------
  # CSVファイルの受け渡し用バケット。incoming/配下へのアップロードが取込のトリガーになり、
  # export/配下にCSV出力の結果が置かれる。
  DataBucket:
    Type: AWS::S3::Bucket
    Properties:
      # バケット名を明示的な固定文字列にしている（自動生成名にしない）。
      # 理由: 下のLambdaのIAMポリシーがこの名前を「!Ref DataBucket」ではなく同じ文字列で
      # 直接参照できるようにするため。!Ref DataBucketを使うと「ロール→バケット」の依存関係が
      # 生まれ、S3イベント通知の「バケット→関数」の依存関係と合わさって、CloudFormationが
      # 拒否する循環依存になってしまう。
      BucketName: !Sub "${AWS::StackName}-data-${AWS::AccountId}"

  # --------------------------------------------------------------------
  # Cognito: 従業員認証用ユーザープール（ユーザー名=社員番号）
  # --------------------------------------------------------------------
  # 従業員のログイン認証を担うユーザープール。ユーザー名には社員番号をそのまま使う運用にしている。
  UserPool:
    Type: AWS::Cognito::UserPool
    Properties:
      UserPoolName: employee-portal-users
      AdminCreateUserConfig:
        # セルフサインアップを禁止し、ImportCsvFunctionによる管理者操作（AdminCreateUser）でのみ
        # ユーザーを作成できるようにする
        AllowAdminCreateUserOnly: true
      Policies:
        PasswordPolicy:
          # 初期パスワードが「社員番号+生年月日」という数字のみの組み合わせになるため、
          # 英大文字・小文字の必須条件は外している
          MinimumLength: 8
          RequireUppercase: false
          RequireLowercase: false
          RequireNumbers: true
          RequireSymbols: false

  # フロントエンド（ブラウザのJavaScript）がCognitoへログインリクエストを送る際に使うアプリクライアント
  UserPoolClient:
    Type: AWS::Cognito::UserPoolClient
    Properties:
      UserPoolId: !Ref UserPool
      GenerateSecret: false  # ブラウザから直接呼ぶ（サーバーサイドを介さない）ためシークレットは発行しない
      # ブラウザから直接ID/パスワードでログインする方式（USER_PASSWORD_AUTH）を許可する
      ExplicitAuthFlows:
        - ALLOW_USER_PASSWORD_AUTH
        - ALLOW_ADMIN_USER_PASSWORD_AUTH
        - ALLOW_REFRESH_TOKEN_AUTH

  # --------------------------------------------------------------------
  # API Gateway (HTTP API) + Cognito JWT オーソライザー
  # --------------------------------------------------------------------
  # フロントエンドが呼び出すAPI本体。GET/PUT /me の2つのルートを持つ（各Lambda定義のEventsで宣言）。
  HttpApi:
    Type: AWS::Serverless::HttpApi
    Properties:
      # ブラウザ（portal.tokaiec.co.jp）からのクロスオリジンリクエストを許可するCORS設定
      CorsConfiguration:
        AllowOrigins:
          - !Sub "https://${DomainName}"
        AllowMethods:
          - GET
          - PUT
          - OPTIONS  # CORSのプリフライトリクエスト用
        AllowHeaders:
          - content-type
          - authorization  # Bearer トークンを送るために必要
      # 全ルート共通の認可設定。Cognitoが発行したIDトークン（JWT）を検証する
      Auth:
        Authorizers:
          CognitoAuthorizer:
            JwtConfiguration:
              # このユーザープールが発行したトークンのみ受け付ける（発行者の検証）
              issuer: !Sub "https://cognito-idp.${AWS::Region}.amazonaws.com/${UserPool}"
              # このアプリクライアント向けに発行されたトークンのみ受け付ける（audienceの検証）
              audience:
                - !Ref UserPoolClient
            # トークンをどこから読むか（Authorizationヘッダーの値をそのままJWTとして扱う）
            IdentitySource: "$request.header.Authorization"
        DefaultAuthorizer: CognitoAuthorizer  # 個別ルートで上書きしない限りこの認可を必須にする

  # --------------------------------------------------------------------
  # Lambda: 本人情報の取得
  # --------------------------------------------------------------------
  # GET /me の実処理。ログイン中の本人のレコードだけをDynamoDBから返す。
  GetEmployeeFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: src/get_employee/   # このディレクトリがzip化されてLambdaにアップロードされる
      Handler: app.handler          # app.pyのhandler関数がエントリーポイント
      Environment:
        Variables:
          TABLE_NAME: !Ref EmployeeTable
          PK_ATTRIBUTE_NAME: "社員番号"
      # このLambda専用のIAM権限。DynamoDBの読み取りのみ許可（最小権限の原則）
      Policies:
        - DynamoDBReadPolicy:
            TableName: !Ref EmployeeTable
      # API GatewayのGET /meからこの関数を呼び出す、というルーティング設定
      Events:
        Get:
          Type: HttpApi
          Properties:
            ApiId: !Ref HttpApi
            Path: /me
            Method: get

  # --------------------------------------------------------------------
  # Lambda: 本人情報の更新
  # --------------------------------------------------------------------
  # PUT /me の実処理。本人のレコードを更新し、変更日時を記録する。
  UpdateEmployeeFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: src/update_employee/
      Handler: app.handler
      Environment:
        Variables:
          TABLE_NAME: !Ref EmployeeTable
          PK_ATTRIBUTE_NAME: "社員番号"
      # 読み取りに加えて書き込みも必要なため、Read専用ではなくCrud（Create/Read/Update/Delete）権限を付与
      Policies:
        - DynamoDBCrudPolicy:
            TableName: !Ref EmployeeTable
      Events:
        Put:
          Type: HttpApi
          Properties:
            ApiId: !Ref HttpApi
            Path: /me
            Method: put

  # --------------------------------------------------------------------
  # Lambda: CSV取込（DataBucketのincoming/プレフィックスへのアップロードでトリガー）
  # --------------------------------------------------------------------
  # CSV取込の実処理。DataBucketのincoming/へのアップロードをトリガーに自動起動する。
  ImportCsvFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: src/import_csv/
      Handler: app.handler
      Timeout: 60  # CSV件数によっては既定の30秒では足りない可能性があるため延長
      Environment:
        Variables:
          TABLE_NAME: !Ref EmployeeTable
          PK_ATTRIBUTE_NAME: "社員番号"        # CSVのどの列を主キーにするか
          BIRTH_DATE_ATTRIBUTE_NAME: "生年月日"  # 初期パスワード生成に使う列
          USER_POOL_ID: !Ref UserPool
      Policies:
        - DynamoDBCrudPolicy:
            TableName: !Ref EmployeeTable
        # S3の読み取り権限。BucketNameはDataBucketの物理名と同じ文字列を直接指定している
        # （循環依存を避けるため!Ref DataBucketを使わない。理由はDataBucketリソースのコメント参照）
        - S3ReadPolicy:
            BucketName: !Sub "${AWS::StackName}-data-${AWS::AccountId}"
        # Cognitoユーザーの作成・照会・パスワード設定を行うための追加権限（SAMの定型ポリシーには無いため直接記述）
        - Statement:
            - Effect: Allow
              Action:
                - cognito-idp:AdminCreateUser        # 新規ユーザー作成
                - cognito-idp:AdminGetUser            # 既存ユーザーか確認（重複作成防止）
                - cognito-idp:AdminSetUserPassword    # パスワードを本パスワードとして確定
              Resource: !GetAtt UserPool.Arn
      # DataBucketへのアップロードで自動起動する、というイベント設定
      Events:
        CsvUploaded:
          Type: S3
          Properties:
            Bucket: !Ref DataBucket
            Events: s3:ObjectCreated:*  # 新規作成・上書きどちらのアップロードでも起動する
            Filter:
              S3Key:
                Rules:
                  - Name: prefix
                    Value: incoming/  # このプレフィックス配下へのアップロードのみが対象（ファイル名は問わない）

  # --------------------------------------------------------------------
  # Lambda: CSV出力（管理者が`aws lambda invoke`等で手動実行）
  # --------------------------------------------------------------------
  # CSV出力の実処理。自動トリガーは設定しておらず、管理者が手動で実行する。
  ExportCsvFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: src/export_csv/
      Handler: app.handler
      Timeout: 60  # 全件スキャンに時間がかかる可能性を考慮して延長
      Environment:
        Variables:
          TABLE_NAME: !Ref EmployeeTable
          PK_ATTRIBUTE_NAME: "社員番号"  # 出力時の並び替えキーにも使う
          DATA_BUCKET: !Sub "${AWS::StackName}-data-${AWS::AccountId}"  # 出力先バケット名
      Policies:
        - DynamoDBReadPolicy:
            TableName: !Ref EmployeeTable
        # 出力したCSVをS3に書き込むための権限
        - S3WritePolicy:
            BucketName: !Sub "${AWS::StackName}-data-${AWS::AccountId}"
