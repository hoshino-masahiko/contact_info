Design Notes

押さえておきたい設計判断

  • S3直アクセスの遮断: CloudFrontがS3への転送時にだけ秘密のRefererヘッダーを付与し、S3バケットポリシーはその値が一致する場合のみ許可します。秘密値自体はパラメータ（NoEcho）として管理しており、この文書にも記載していません。
  • 初期パスワード: 「社員番号＋生年月日」を作成時点で本パスワードとして確定（AdminSetUserPassword）。初回ログイン時の強制変更は発生しません。
  • データの一意キー: 元のCSVに一意キーがなかったため、先頭列として社員番号を追加。CognitoのユーザーIDもこの社員番号をそのまま使います。
  • 承認フロー: なし。従業員本人の変更はそのままDynamoDBに反映されます。変更のたびに「変更日時」（JST・年月日時分）を上書き記録しますが、過去の変更履歴（誰が何を変えたか）までは保持していません。
  • 属性名がそのまま日本語: DynamoDBの属性名・CSVの列見出しはどちらも同じ日本語（社員番号・氏名…）。取込・出力のロジックが列名を仲介せずそのまま使えるようにするための設計です。
  • CSV取込時の文字コード: UTF-8（BOM付き含む）を優先的に試し、UTF-8として読めない場合はShift-JIS（cp932）にフォールバックする自動判定。取込元がExcelでもモダンなシステム由来でも、どちらの保存形式でも取り込める。
  • CSV取込時の上書きルール: 同じ社員番号が既存レコードとして存在する場合、CSVの値をそのまま（空欄・スペースも含めて）上書きする。空欄の列は既存の値を空文字で上書きするため、見た目上は「その項目を削除した」のと同じ結果になる（意図的な仕様）。CSVに列そのものが存在しない属性（「変更日時」など）だけは、既存の値を引き継ぐ。
Follow-up

個別確認で出た論点の補足

ここまでのやり取りで具体的に確認した4点を記録しておきます。

Refererの「一致」とは何と何か

一致させているのは、CloudFrontがS3への転送時に付けるRefererヘッダーの値と、S3バケットポリシーが要求するRefererヘッダーの値です。どちらも同じ1つの秘密文字列（OriginVerifySecretパラメータ）を参照しているため、常に一致します。ブラウザ本来のRefererとは無関係に、CloudFrontが原点向け通信でだけ独自の合言葉として上書きしています。

経路S3が受け取るReferer判定
ブラウザ→CloudFront→S3秘密文字列と一致（CloudFrontが必ず付け替える）許可（200）
ブラウザ→S3に直接アクセス付いていない／別の値拒否（403）

CSVのデータはいつDynamoDBへ移るか

S3のincoming/へのアップロードが完了した瞬間に、S3イベント経由でImportCsvFunctionが自動起動し、DynamoDBへ書き込まれます（Figure 2 の①→自動起動）。ログインのタイミングでは何も起きません。GET/PUT /meはDynamoDBだけを参照しており、S3には一切アクセスしません。つまり「ログイン後に表示される情報」は、ログインより前のアップロード時点で既にDynamoDBへコピー済みだったものです。

取込ファイル名は任意か

任意です。S3イベントのトリガー条件は incoming/ というプレフィックス（フォルダ）のみで、ファイル名は判定していません。incoming/配下であればファイル名は何でも取込が起動します。

列（項目）を追加できるか

CSV取込とAPIは列名をハードコードしていないため、新しい列を追加してもそのままDynamoDBに保存されます。ただしWebフォームとCSV出力は列の一覧をコードに持っているため、そこまで反映するには小さな修正が必要です。

処理列名の扱い
CSV取込 → DynamoDBヘッダー行の列名をそのまま属性名として使用。新しい列があっても無改修で保存される
閲覧・編集API（GET/PUT /me）DynamoDBの中身をそのまま返す/書く。無改修で通る
Webフォーム（GitHubfrontend/app.js）表示する列の一覧がコードに直書き。画面に出すにはここへ追記が必要
CSV出力（GitHubsrc/export_csv/app.py）出力する列の一覧がコードに直書き。出力に含めるにはここへ追記が必要

例: 緊急連絡先に住所列を追加する場合 — ①CSVに列を追加してアップロード（保存は無改修で完了）→ ②画面で見せたいならfrontend/app.jsのフィールド一覧に追記 → ③出力にも含めたいならsrc/export_csv/app.pyのHEADERに追記（いずれもリポジトリルート基準のパス）。

画面の項目の並び順ルール

DynamoDBは属性（map）に決まった並び順を持たないスキーマレスなドキュメントストアです。コンソールで見える順序は実装依存で、保証された仕様ではありません。画面・CSV取込・CSV出力はそれぞれ別々の順序定義を持っており、DynamoDB内部の並びとは無関係です。

順序決めているもの
画面の表示順GitHubfrontend/app.js の FIELD_GROUPS 配列（唯一の正）
CSV取込時の列ローカルアップロードするCSVファイルのヘッダー行そのもの
CSV出力時の列順GitHubsrc/export_csv/app.py の HEADER 定数
DynamoDB内部の並び保証なし（スキーマレスのため、コンソール表示順が変わることもある）

この4つを意図的に疎結合にしているため、DynamoDBの並びを気にせず列を追加・変更できます（列追加については上記参照）。

Changelog

初回デプロイ後の変更点

  • ポータル名称: 画面タイトル・タブタイトルを「緊急連絡先登録ポータル」に変更。保存ボタンのラベルを「登録する」→「変更する」に変更。
  • 案内文の追加: タイトル直下に「電話番号は個人所有（会社貸与ではなく）を入力」「変更後は画面下の『変更する』を押す」の2行を表示。
  • CSVフォーマットの正式確定: 取り込むCSVを21列（Data Dictionary参照）の正式フォーマットとして確定。画面の項目名・並び順はこのCSVの列名・列順にそのまま従う（詳細はFollow-upの「画面の項目の並び順ルール」）。取込処理（GitHubsrc/import_csv/app.py）は列名を決め打ちしない設計のため無改修、画面（GitHubfrontend/app.js）とCSV出力（GitHubsrc/export_csv/app.py）は列名に合わせて改修。あわせて文字コードをUTF-8（BOM付き）優先・Shift-JISへの自動フォールバックに変更。
  • 変更日時の記録・表示: UpdateEmployeeFunctionが保存の都度「変更日時」属性（JST・年月日時分、例: 2026-09-09 15:49）をサーバー側で上書き記録（クライアントからの入力では変更不可）。画面はログアウトボタンの右隣に表示。
  • 保存メッセージの表示位置: 「登録しました」等のメッセージを画面上部から、ボタン直下（画面最下部）に移動。ボタン押下後にスクロールなしで見えるようにするための変更。ログイン時のエラーメッセージは引き続き画面上部に表示。
概要レベルの資料です。各リソースの詳細設定（IAMポリシーの中身、DynamoDBのキャパシティ設定など）は個別に確認しながら深掘りください。
